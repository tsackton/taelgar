Taelgar Git secret filter
=========================

Purpose
-------

This is a low-stakes DM spoiler filter for sharing notes with trusted players.
It is not a security mechanism for passwords or credentials. An occasional
spoiler slipping through is a minor failure, not a credential exposure incident.

Markdown notes may contain raw DM-only fragments. Git stores deterministic
placeholders while the authorized working copy stores the original fragments
under .secrets-v2. The previous numeric placeholders and flat .secrets files
remain readable for recovery.

Filtering and checks
--------------------

* The implementation and hooks are tracked in _scripts.
* A path-specific include in the user's global Git configuration survives
  recreation of this repository's .git directory.
* Git's persistent process interface runs one Python process for all filtered
  files in a Git command, instead of starting Python once per Markdown file.
  The process exits with that Git command; it is not a background service.
  Single-file clean and smudge commands remain available for compatibility.
* The filter is required, so a missing or failing implementation stops Git.
* The pre-commit hook checks staged Markdown changes for raw DM markers.
* For an existing remote branch, pre-push checks commits beyond its remote tip.
  For a new branch, it checks only commits not reachable from known local
  remote-tracking refs, including refs for other remotes. Already shared history
  is not re-audited. Fetching before pushing keeps that baseline current.
* If a new branch has no known shared ancestor (including a checkout with no
  remote-tracking refs), pre-push checks the current Markdown tree only. It does
  not inspect old commits. Branch deletion needs no content check.
* Recovery sidecars use the note's full repository path, are written
  atomically, and are restricted to the current user.
* Unclosed or overlapping markers fail closed.
* A repository workflow checks both the tests and the committed tree.

Activation
----------

Run:

    python3 _scripts/install_secret_filter.py

Then verify at any time with:

    python3 _scripts/install_secret_filter.py --check

Before replacing history or changing branches, snapshot all currently visible
DM fragments into the v2 recovery store:

    python3 _scripts/secret_filter.py snapshot-working-tree

Existing installations that include _scripts/secret-filter.gitconfig pick up
the persistent process automatically after these tracked files are updated.
Cloud checkouts need those updates too; they do not need a copy of the local
recovery store unless they need to restore DM text. Missing recovery entries
leave their placeholders intact.

Installation does not require an audit or cleanup of old Git history. If the
current committed notes still contain raw DM markers, activating the filter may
make them appear modified as Git compares their filtered versions.
