# Extract time markers — experimental draft

The purpose of this uninstalled draft is **source UID → inferred time or duration → evidence**, for each temporal assertion. This framing governs every extraction decision. Context, relationships, provenance, and the YAML check support interpreting those records; they never replace or compress them. Never combine time markers, including repetitions, confirmations, or corrections. Read [the time-marker format](references/format.md) before authoring. It supersedes the time A/B requirements in the older shared experimental contract. All generated files remain under `_sessions/time-location-testing`; do not install this skill or write into live bundles during the experiment. Existing pilot outputs and their builders use the old format and must not be overwritten as part of a new extraction.

Resolve the existing session YAML and its registered polished transcript. Record source/YAML fingerprints before reading. Preserve source-local UIDs and whole polished-turn mappings; session + source revision + UID identifies evidence. Do not substitute a recap or use recording runtime as world time.

Read the complete transcript sequentially, including combat, lore, and chatter, before calling extraction complete; reread truncated output. Search is a supplementary checklist, not a substitute for reading. Look for dates, bare clock answers, time-of-day cues, rests, sleep/waking, elapsed intervals, compressed travel, and frame changes. Resolve question/answer pairs, accepted proposals, corrections, and retrospective confirmations using surrounding speech. A smaller output does not justify a narrower reading method. Record any concrete source or reading limitation that affects the extraction in optional top-level `limitations`; do not include reading-window logs or review-status fields.

Author one marker per temporal assertion in source order: its source UID/range, inferred time or duration, and exact evidence. Preserve separate assertions even when they describe the same event, repeat a value, occur in adjacent turns, or share a UID. Opening morning and a later approximate clock are separate markers; sleeping overnight and a later next-morning date are separate markers. A single narrated six-day interval can be one marker, but a separately stated endpoint date remains another. Supporting context may be quoted without absorbing the marker belonging to another temporal assertion. Exclude routine table-time false positives; do not discard in-world assertions because they repeat, are later rejected, or add no new elapsed time. Keep vague quantities vague. Label inferred values and YAML-derived date components; do not assign a date or clock to every passage.

Use `reading` for the interpretation, `basis` for why a structured value is supported, and optional `note` only for a material qualification not already expressed. Do not repeat the same explanation across these fields or put generic extraction instructions in the output. This prose discipline never authorizes deleting or merging assertions or their evidence.

Use optional context, actors, completion, and marker relationships for complications. Record flashback entry and return when identifiable; uncertainty about the return remains explicit. A retcon may insert an earlier scene without replacing an existing claim. Keep the original assertion and its correction as separate markers, even for an immediate self-correction within one turn; link the correction with `revises` when supersession is established. Mark containment, partial overlap, or the same interval only when evidenced; split actors alone do not prove concurrency. Retain retrospective confirmations as their own markers while making clear that they do not establish another rest or additional elapsed time. A study interval already containing a rest must not gain another hour. Preserve local-clock changes on teleport without inventing elapsed time or geographic offsets.

Use the user's one-hour short-rest/eight-hour long-rest conventions as labeled assumptions when a rest is established. A proposed or interrupted rest does not establish its full duration. Overnight is not exactly eight hours; rest benefits alone do not prove that narration reached morning. Preserve completed overnights and multi-day jumps without turning overlapping accounts into additive durations.

Compare the narrated current-play span with YAML using exactly `matched`, `compatible`, or `conflict`, as defined in the format reference. YAML start may anchor a relative span if disclosed; never infer missing days from YAML end and use them to validate that end. Check independently spoken dates too. Assess current play excluding retrospective scenes; there is no configurable scope field. Record ambiguous opening/closing long rests as boundary uncertainties for later cross-session review, not automatic date corrections. Historical YAML used multiple boundary conventions; flag a conflict only when no reasonable supported boundary reading reconciles it. Do not normalize dates or require adjacent ranges to share a date.

Recheck actual advances, both ends of jumps, actor scope, frame changes, bedtime/departure framing, and contradictory speech. Check that each temporal assertion retains its own marker at its source position: no combined morning/clock, overnight/waking-date, duration/endpoint, or original/corrected assertions, and no dropped repetitions. Later evidence may support an inference at an earlier marker but must not silently move a later clock reading to that earlier moment. Verify source hashes, quotation membership, whole-turn UID boundaries, marker references, structured values, and the YAML assessment. Incomplete reading must be labeled and cannot produce `matched`; structural checks do not certify semantic completeness. Existing pilot builders neither extract arbitrary transcripts nor validate this revised format.

Deliver `time-markers.json` in the agreed experimental output directory, with a concise handoff of the YAML result and material uncertainties. No second timeline, constraints table, or mandatory HTML/table artifact. Preserve human corrections and stable marker IDs when revising; changed sources require reinspection rather than replacing hashes to pass checks. Record uncertainties without stopping over incidental wording. Do not edit YAML, transcripts, canonical dates, location artifacts, installed skills, or later timeline outputs unless separately requested.
